# wyf 的博客 · 独立 Markdown 文章版

GitHub Pages 静态博客，无需构建或服务器。保留原动漫背景、公式排版和本地写作功能。

## 本次升级

解压 `wyf-blog-upgrade.zip`，将里面的文件和文件夹一起上传到仓库根目录，覆盖同名文件。`posts/` 文件夹需要保持这个名称和层级。此次升级已迁移仓库中四篇现有文章，包含 `[ZJOI2022] 树`，正文保持原样。背景、样式和已有第三方组件无需重新上传。

如果你在下载升级包后又发布了文章，请先备份当前 posts.json。新版兼容旧版包含完整正文的 posts.json；可以先只更新代码，保留你的最新 posts.json，然后在写作区导入最新旧版文件、导出更新包，完成迁移，避免被升级包内较早的文章列表覆盖。

## 文件结构

- `posts.json`：轻量索引，只有 ID、标题、日期、分类、摘要、字数、正文文件路径、正文版本摘要。**不包含文章正文**。
- `posts/<文章ID>.md`：每篇文章独立的 Markdown 正文。
- `index.html`、`style.css`：页面与样式。
- `app.js`、`blog-data.js`：按需读取文章、本地写作、增量导出和数据校验。
- `assets/hero.png`：原有动漫背景。
- `vendor/`：本地 Marked、DOMPurify、KaTeX 和新增 JSZip 3.10.1、js-sha256 0.11.1，附许可证，无 CDN 依赖。

首页只读取 posts.json，搜索匹配标题和摘要。点击文章或在写作区选择文章时，才读取对应的一个 Markdown 文件。索引仍会随文章数量增长，但不再随全部正文的长度增长。

## 日常发布

1. 点击「写博客」→「新建文章」，输入标题、日期、分类和正文。
2. 勾选「选入发布」。已有文章保持勾选。
3. 点击「导出发布更新包」，再点击出现的「下载 blog-update.zip」，保存更新包。
4. **解压**更新包，把里面的 `posts.json` 和 `posts` 文件夹一起拖到 GitHub 仓库根目录的 Add file → Upload files 页面，再 Commit changes。不要上传 ZIP 本身，也不要删除仓库中原有的其他正文。
5. 等 Pages 部署完成后刷新网站。刷新写作页后，已提交的修改会标为「已发布」。

每次更新包仅包含完整轻量索引及新增、修改过的 Markdown 文件。不重新打包全部正文。尚未上传的更新不会被当成已发布，下次导出仍包含它们。导出前会读取网站上的最新索引，并保留其他设备新发布的文章。如果同一篇文章在另一台设备上也有修改，会阻止覆盖并提示先备份、合并。

修改旧文章：选择文章、修改，再导出提交。取消勾选或删除本地副本后，提交新索引会从网站列表隐藏该文；仓库中的旧 .md 文件仍保留，若要彻底删除，请在 GitHub 中删除对应文件。

## 草稿与旧版迁移

- 草稿只保存在当前浏览器 localStorage，不会自动公开或跨设备同步。
- 新版首次进入写作区会读取旧版草稿，保留未发布内容，旧存储也不删除。
- 「导入 / 恢复」支持旧版完整 posts.json、旧版草稿备份、新版轻量索引和完整备份。旧正文会在下次发布时转换成单独的 .md 文件。
- 导入会提示确认，并替换本地列表。建议先展开下方帮助，点击「备份全部草稿」。备份会加载全部文章正文，适合迁移或备份，不是日常发布文件。
- 备份包含未发布内容，不要上传到公开仓库。清理浏览器数据前务必备份。
- 导入新版索引后，正文从当前网站的 posts/ 文件加载。离线迁移到其他站点应使用完整备份，或复制完整 posts/ 目录。
- 若正文未上传或路径不对，文章页会显示错误并提供重试，不会把加载失败当成空文章覆盖。

## 本地预览

执行 `python3 -m http.server 8000`，打开 http://localhost:8000 。不要双击 HTML 文件；fetch 无法正常读取本地文章。
